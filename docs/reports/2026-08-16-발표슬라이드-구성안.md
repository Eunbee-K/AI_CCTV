# 2차 심사 발표 슬라이드 구성안

**작성** 2026-08-16 · **바탕** [2차심사 발표준비](2026-08-15-2차심사-발표준비.md)
**발표** 7분 + 질의응답 5분

## 이 구성의 뼈대

기존 준비 문서는 "설명 → 시연" 순서였는데, **"시연 먼저, 설명은 되짚기로"** 로
바꾼다. 심사위원이 무엇을 보는 건지 알고 나서 기술 설명을 들어야 이해가 붙는다.

```
Ⅰ. 왜 만들었나            (1분)   ← 문제 정의 + 목적
Ⅱ. 무엇을 만들었나 — 시연  (1분)   ← 영상으로 전 과정 한 번에
Ⅲ. 어떻게 동작하나         (3분)   ← 유저플로우를 따라가며 되짚기
   └ 각 단계에서 기술 설명을 얹는다 (CLS/DET, 성능, 보고서 출력)
Ⅳ. 성과와 확산            (1분 30초)
Ⅴ. 마무리                 (30초)
```

**한 슬라이드 = 한 메시지.** 7분에 13장이면 장당 30초라, 슬라이드에 글을 채우면
읽다가 끝난다. 숫자와 그림 위주로.

## 슬라이드별 구성

### 1. 표지 (10초)
- 과제명 · 팀명(수어사이트 스쿼드) · 발표자
- 배경은 실제 관로 내부 사진 한 장

### 2. 문제 정의 (30초) — *Ⅰ*

| 지금 | |
|---|---|
| 현장 1개소(30km) 판독 | **약 40시간 / 1인** |
| 판독 품질 | 숙련도에 따라 편차 |
| 조사표 작성 | 수기 |

- 화면: 왼쪽에 "사람이 영상을 처음부터 끝까지 본다" 그림, 오른쪽에 40시간 강조
- **한 문장으로**: "영상을 다 볼 필요 없이, 봐야 할 곳만 보게 하자"

### 3. 추진 경과 (30초) — *Ⅰ*

| 단계 | 접근 | 확인한 것 |
|---|---|---|
| 1단계 (~상반기) | 생성형 AI 직접 판독 | 신설관로에서 가능성 확인 |
| 2단계 (하반기) | **51만장으로 딥러닝 학습** | 노후관로·위치까지 확장 |
| 3단계 (현재) | **판독기 3중 구조 통합** | 감독자는 확인만 |

- "작년엔 생성형 AI였는데 왜 YOLO냐"에 **먼저** 답하는 슬라이드
- 심사위원 시선에서는 "아이디어를 실제로 구현까지 밀어붙였다"가 강점

---

### 4. 시연 전 한마디 — 왜 로컬인가 (20초) — *Ⅱ*

> **"지금 보실 화면은 이 노트북 한 대에서 도는 겁니다."**

- GPU 서버를 쓰면 더 빠르지만 **월 비용이 발생**한다. 시범 단계에서는
  **로컬 CPU만으로도 동작하도록** 만들어 두었다
- 프레임당 약 0.44초 — 6분 영상이 1~2분
- **보안 측면의 이점**: 관로 위치·GPS가 담긴 영상이 외부로 나가지 않는다
  (망분리 환경에서도 그대로 쓸 수 있다)
- 서버가 준비되면 그쪽 GPU로 넘기는 경로도 설계에 들어 있다

> 이 슬라이드가 "왜 느린가"라는 의문을 미리 막아준다. 변명이 아니라
> **설계 선택**으로 말할 것.

### 5. 시연 영상 (60초) — *Ⅱ*

사전 녹화본 사용(현장 오류 대비). 자막으로 단계 표시:

```
① 영상 올리기        드래그앤드롭
② 분석 실행          진행 로그가 실시간으로
③ 결과 확인          결함 목록 + 영상에 박스 표시
④ 검수·수정          잘못된 건 지우고, 빠진 건 추가
⑤ 보고서 출력        엑셀 / 야장 PDF 즉시 다운로드
```

- **말은 최소로.** "이 다섯 단계가 전부입니다" 정도만
- 40시간 → 몇 분이 눈으로 보이게 하는 것이 목적

---

### 6. 전체 구조 (40초) — *Ⅲ 시작*

- 유저플로우 다이어그램 1장
  (`2026-08-05-전체-유저플로우.md`의 mermaid를 발표용으로 단순화)
- **여기서부터 "방금 보신 것을 단계별로 다시 보겠습니다"** 로 전환
- 각 단계에 번호를 붙여 뒤 슬라이드와 연결

### 7. 판독 구조 — 이 발표의 핵심 (60초) — *Ⅲ*

```
        ┌─ Classification ─┐
프레임 ──┼─ Object Detection ┼── 합집합 ── 결함 후보
        └─ LLM (선택) ─────┘
```

| | 무엇을 하나 | 아는 종류 |
|---|---|---|
| **CLS** | 결함 구간 선별 + 이름 | 24종 |
| **DET** | 위치(박스) + 이름 | 16종 |
| **LLM** | 이름 보강 (선택) | 8종 |

**말할 것 세 가지**

1. **셋이 같은 프레임을 각자 본다** — 순차가 아니라 독립. 하나가 놓쳐도 다른
   쪽이 잡는다
2. **결과는 합집합** — 하나라도 찾으면 후보에 올린다. 놓치는 것을 줄이는 쪽으로
   설계했다(검수자가 지우는 편이 못 찾는 것보다 낫다)
3. **LLM은 껐다 켤 수 있다** — 외부 API라 망분리 환경을 고려

### 8. CLS는 어떻게 만들었나 (40초) — *Ⅲ*

| | |
|---|---|
| 학습 | 24클래스 11,495장 (결함 종류당 400장으로 균등화) |
| 모델 | EfficientNet-B0, 384px, Colab T4 |
| 핵심 설계 | 정상의 20%를 **관 밖(맨홀·지상)**으로 채움 |

- **관 밖 오탐 39% → 0%**가 이 설계의 결과 — 데모에서 보여줄 수 있는 개선점
- 화면: 관 밖 사진 옆에 "이전: 결함 / 지금: 정상" 대비

### 9. DET는 어떻게 만들었나 (40초) — *Ⅲ*

| | |
|---|---|
| 학습 | 18클래스 133,961장 (공공데이터 51만장에서 선별) |
| 모델 | YOLO11-L, 960px, 50 epoch (약 29시간) |
| 결과 | **mAP50 0.703** |

- 화면: 박스가 그려진 결함 사진 3~4장
- 가점 항목(공공데이터 활용)을 여기서 한 줄로 연결

### 10. 성능 — 둘을 합치면 (50초) — *Ⅲ*

**같은 사진으로 두 모델을 비교한 결과** (두 모델 학습분을 모두 제외한 판, 360장)

| | 이름 정확도 |
|---|---|
| DET 단독 | 61.7% |
| CLS 단독 | 40.8% |
| **합치면** | **90.3%** |

- **핵심 메시지**: "겹치는 건 12%뿐 — 둘이 거의 다른 걸 맞힙니다"
- 결함 구간 자체를 놓치지 않는 것은 CLS가 담당: **23종 전부 탐지율 80% 이상,
  14종은 100%**
- 막대그래프 1장으로 (61.7 / 40.8 / 90.3)

> **정직하게 말할 것**: 이 값은 잘라놓은 사진 기준이고, 연속 실영상 검증은
> 다음 단계다. 물어보면 그렇게 답한다(§질의응답).

### 11. 결과물 — 보고서 자동 생성 (40초) — *Ⅲ 마무리*

- **야장 PDF**를 크게 띄운다. 실물 서식과 같은 A4 양식
- **보고서 정보 자동 입력**을 강조:
  자막에서 OCR로 읽어오는 10항목 —
  관로번호 · 관경 · 거리 · 현장명 · 상하류 맨홀번호 · 조사일자 · 관종 ·
  배수방식 · 주행방향 · 위경도
- 화면: 왼쪽 영상 자막 → 오른쪽 야장의 해당 칸으로 화살표
- **"손으로 옮겨 적던 항목이 자동으로 채워집니다"**
