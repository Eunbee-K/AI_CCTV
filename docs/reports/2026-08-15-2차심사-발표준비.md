## 2. 슬라이드별 상세 구성

### Ⅰ-1. 문제 정의 (구 슬라이드4 그대로 사용 가능)

- 기존: 관로시공 → CCTV촬영 → **감독자 육안판독(숙련도 편차)** → 시공품질확인
- 변경: 같은 흐름에서 판독 단계를 AI가 대체, 감독자는 최종 확인만
- 신청서(붙임1) 문구 그대로 사용: "판독 소요시간 현장 1개소(30km) 기준 약 40시간/1인"
- **일반인 대상 포인트**: 이 슬라이드는 코딩 지식이 전혀 없어도 이해되는 부분이므로
  발표 도입부(30초 이내)에 빠르게 지나가고, 다음 장부터 "무엇을 만들었는지"로 넘어간다

### Ⅰ-2. 추진 경과 (구 슬라이드6 재구성 — 유사사례 비교 → 진화 서사로)

작년 슬라이드는 표 형태로 "공단 사례 vs 유사사례"를 비교했는데, 이번엔 **자기 프로젝트의
시간순 진화**로 바꾸는 걸 제안한다.

| 단계 | 시기 | 접근 | 확인된 것 |
|---|---|---|---|
| 1단계 (아이디어 검증) | ~2026 상반기 | 생성형 AI(Gemini/ChatGPT) 직접 판독, 소량(결함항목당 20~30장) | 신설관로처럼 결함이 단순한 영역에서 신뢰도 평균 85% — **가설이 통한다는 것을 저비용으로 먼저 확인** |
| 2단계 (본격 구축, 현재) | 2026 하반기 | 공공데이터포털 하수관로 이미지 **51만장**으로 YOLO 딥러닝 모델 학습 | 결함 위치까지 픽셀 단위로 탐지, 노후관로 등 복잡한 결함까지 확장 |
| 3단계 (통합) | 현재 진행 | **필터(1차 선별) + YOLO(위치·명칭) + LLM(3차 의견)** 3중 구조로 통합 | 감독자가 최종 판단만 하면 되는 Human-in-the-Loop 완성 |

이 구성이면 "왜 방향이 바뀌었나"라는 질문을 심사위원이 하기 전에 발표자가 먼저 답한
모양이 된다. 그리고 "작게 시작해서 검증하고 크게 키웠다"는 서사는 효과성·문제해결능력
항목에서도 유리하다.

### Ⅱ-1. 시스템 아키텍처 (신규 — 가장 공들여야 할 슬라이드)

전문가 심사위원에게 "이 팀은 실제로 시스템을 설계할 줄 안다"를 보여주는 슬라이드.
**순차 3단이 아니라 필터+YOLO가 나란히 판독하는 구조**를 다이어그램 한 장으로:

```
[영상 입력]
     │  1초 간격 프레임 추출
     ▼
┌───────────────────────────────────────────┐
│  정상/결함 필터 (EfficientNet-B0, 24클래스)   │  ← "이 구간이 결함인가, 무엇인가"
│  영상 내 상대 순위 상위 20%를 구간(행)으로 선별│
│  결함 종류까지 1차로 이름을 낸다(확신 90%↑만) │
└───────────────────────────────────────────┘
     │  결함 의심 구간마다
     ├──────────────────────┐
     ▼                      ▼
┌──────────────────┐  ┌──────────────────────┐
│  YOLO 결함탐지(16종) │  │  LLM 3차 의견 (선택)   │
│  바운딩박스+이름+conf│  │  Gemini+GPT, 기본 꺼짐 │
└──────────────────┘  └──────────────────────┘
     │  이름이 여러 개면 후보로 나란히 (박스는 YOLO만)
     ▼
[감독자 최종 승인] → [엑셀 조사표 / 야장 PDF 자동 생성]
```

발표 포인트:
- **왜 필터와 YOLO를 나란히 쓰는가**: 필터만 쓰면 위치(박스)를 못 그리고, YOLO만 쓰면
  전체 프레임을 다 훑어야 해서 느리다. 필터가 먼저 "볼 가치가 있는 구간"을 추리고 그
  구간에 YOLO가 위치까지 정밀 판독한다 — **속도와 정확도를 동시에 잡는다**는 설계 의도.
- **필터가 이름도 낸다는 게 이번 구조의 핵심**: 필터(다중분류)가 확신이 높을 때(90%↑)
  결함 종류까지 1차로 답을 낸다. YOLO가 놓치는 종류(위치 특징이 약한 결함)를 필터가
  메우고, 반대로 필터가 헷갈리는 종류(이음부 계열 등 위치·형태 정보가 필요한 것)는
  YOLO가 메운다 — 서로 다른 약점을 보완하는 관계.
- **LLM은 왜 선택 기능인가**: 회사 내부망에서는 외부 API 호출이 막히므로 기본은 꺼두고,
  필요할 때만 세 번째 의견으로 켠다 — 보안성과 유연성을 동시에 챙긴 설계라는 점을 강조.
  (신청서 원안의 "보안성 — 딥러닝 로컬모델로 인터넷 의존도 제거" 문구와 자연스럽게 연결)
- **일반인 대상 설명**: "사람이 CCTV를 볼 때도 '일단 수상한 구간만 골라본 다음(필터가
  위치와 1차 이름을), 정확한 위치와 모양을 확인하고(YOLO), 애매하면 다른 사람 의견도
  들어본다(LLM)'는 확인 절차와 똑같은 구조"라고 비유하면 전달력이 올라간다.

### Ⅱ-2. 유저플로우 (신규)

`docs/reports/2026-08-05-전체-유저플로우.md`의 mermaid 다이어그램을 발표용으로 단순화.
심사위원이 "실제로 감독자가 이걸 쓸 수 있는가"를 확인하는 슬라이드이므로 **화면 스크린샷과
함께** 배치하는 것을 권장.

```
① 영상 등록          드래그앤드롭으로 여러 개 한 번에
        ↓
② 분석 실행          진행률 실시간 표시 (프레임추출 → 필터 → YOLO → OCR)
        ↓
③ 결과 검토           재생하며 결함 위치로 바로 이동, 오탐 체크, 값 수정
        ↓
④ 보고서 정보 확인     현장명·관경·거리 등 자막에서 OCR로 자동 채움
        ↓
⑤ 보고서 출력         엑셀 조사표 / 파이프에셋 야장 PDF 즉시 다운로드
```

포인트: "①~⑤ 전 과정이 감독자 1인 조작만으로 끝난다" — 신청서의 90% 절감 근거가
바로 이 화면 흐름에서 나온다는 것을 시각적으로 보여준다.

### Ⅱ-3. 학습데이터 구축 (구 슬라이드9 계승 + 갱신)

- 공공데이터포털 하수관로 내부 이미지 데이터 **약 51만장**
- 「하수관로·맨홀조사 및 상태 등급 판단기준 표준 매뉴얼」 기준 **결함 코드 체계**
  - 신청서 원안은 "약 20개"였는데, 실제 구축된 마스터 코드표는 **31종**(CLAUDE.md 코드표)이다.
    YOLO(test3)는 그중 **16종**을 위치까지 학습했고, **필터(분류기)는 24종을 전부 배워
    YOLO가 모르는 종류까지 이름을 낸다** — 그래서 실사용 커버리지는 YOLO 단독보다 넓다.
    "31종 체계 중 위치 탐지는 16종, 필터가 그 외 종류까지 이름으로 보완, 나머지는 순차
    확대" 라고 정직하게 말하는 편이 효과성 항목에서 오히려 신뢰를 준다
    (아래 4장 "발표 시 숫자 정리" 참고)
- 사진(jpg) + 라벨(bbox 좌표 + 클래스) 구조는 구 슬라이드9 이미지 그대로 재사용 가능

### Ⅱ-4. 결함탐지 파이프라인 상세

- 구 슬라이드11(청크 전송 다이어그램)은 "Gemini/ChatGPT에 프레임을 나눠 보낸다"는
  1단계 시절 구조 — 지금은 YOLO가 메인이므로 **다이어그램의 주어를 YOLO로 교체**하고,
  LLM은 위 아키텍처 슬라이드에서 이미 다뤘으므로 여기서는 생략하거나 간단히 각주로만.

  **정확도를 지키기 위한 후처리 단계**를 한 줄씩 넣으면 완성도 점수에 도움된다.

### Ⅲ. 산출물 시연

- 산출물 서식 요건(붙임2)의 "실제 기동 또는 기동 화면 동영상"에 해당.
- 실제 영상 1건을 넣고 ①영상 등록 → ②분석 실행(진행률) → ③결과표에 결함이 채워지는 것
  → ④엑셀/야장 PDF 다운로드까지 30~60초 분량으로 녹화해 삽입.
- **오류 가능성 대비해 사전 녹화본 사용 권장**(산출물 서식 안내 문구와 동일한 이유).

### Ⅳ-1. 정확도·성능 실측 (신규 — 효과성 30점의 핵심 근거)

작년 발표는 "신뢰도 평균 85%"(생성형 AI, 신설관로 한정) 한 줄이 전부였다. 이번엔 실측
수치가 있고, **특히 필터 쪽은 이제 자신 있게 앞세울 수 있는 숫자다**(아래 참고).

| 항목 | 수치 | 비고 |
|---|--:|---|
| 필터(분류기) AUC | **0.9906** | 결함/정상 구분 정확도. 잘라놓은 검증셋 455장 기준 |
| 필터 결함 재현율 | **96.0%** | 정상 오탐 5% 허용 시. 결함 455장 중 437장 검출 |
| 필터 관 밖(맨홀 등) 오탐 | **0%** | 옛 버전(v3)은 39%였던 문제를 해결 |
| YOLO(test3) 16종 결함탐지 mAP50 | 0.703 | test3, 워크스테이션 학습 로그 기준 |
| 학습 이미지 규모 | 약 51만장 (공공데이터포털) | 가점 항목과 연결 |

**필터 수치를 "신중히 감추자"던 이전 판단은 철회한다.** 8/12 시점엔 실영상 연속검증
AUC가 0.52까지 떨어진 것이 확인돼 신중론을 폈는데, **그 측정 자체가 무효였다** —
검증셋 정답을 프레임 단위로 찍지 않고 조사표 거리 기록에서 펼쳐 만들어, 정답 결함
구간이 전체의 24.6%까지 부풀어 있었다. 즉 0.52는 필터가 아니라 그 라벨을 잰 값이다.
(그 밖에 관 밖 프레임 오판은 실제 문제였고 v6에서 39%→0%로 고쳤다.) 8/15 재구축(v6)으로 위 표의 값이 나왔고, **관 밖 오탐이 39%→0%로 사라진
것**은 데모에서 시연 가능한 확실한 개선점이다.

**다만 "잘라놓은 사진 판" 값이라는 단서는 여전히 필요하다.** 위 표는 결함이 확실히
찍힌 사진(정상:결함 비율을 인위적으로 맞춘 판)에서 잰 것이고, **실제 연속 영상에서의
검증(베타테스트)은 아직 진행 전**이다. 발표에서는 "검증 데이터셋 기준 실측"이라고
정확히 표기하고, 질의응답에서 실영상 검증 계획을 물으면 진행 예정이라고 답한다
(§4 예상 질문 참고).

**YOLO(test3)는 클래스 편차가 크다** — 야장(실제 조사영상 기반) 검증에서 재현율
36.0%(105/292장)로, 잡는 종류(CL 85%·LP 80%·TO 80%)와 거의 못 잡는 종류(CM·JS·PO 등
0%)가 뚜렷이 갈린다. "우수 항목부터 우선 적용, 필터가 나머지를 보완" 프레이밍을 쓴다.

## 4. 발표 전 숫자 정리 체크리스트

신청서(붙임1)와 실제 개발 진행 상황 사이에 숫자 차이가 있는 항목들. 발표 자료에 넣기
전에 팀 내에서 어느 숫자로 통일할지 정해야 한다.

| 항목 | 신청서(붙임1) 표기 | 현재 실측/진행 상황 | 제안 |
|---|---|---|---|
| 결함 유형 수 | "약 20개 결함 유형 자동 분류" | 마스터 체계 31종, YOLO 16종(위치) + 필터 24종(이름) | "31종 표준 체계, 위치탐지 16종·이름판독 24종으로 순차 확대"로 구체화 |
| 처리 흐름 ③단계 | "판독자 승인" | 구현은 필터+YOLO 병렬 판독(+LLM 선택) 후 승인 | 아키텍처 슬라이드로 대체 설명 |
| 활용기술 | "YOLO" 단독 | 필터(EfficientNet-B0, 다중클래스) + YOLO + LLM(선택) | 병렬 구조로 갱신 |
| 프레임 추출 간격 | "1~2초 간격" | 1초로 확정(2초는 결함 누락 확인되어 폐기) | "1초 간격"으로 통일 |
| 정확도 | (없음, 유사사례 표만 있음) | 필터 AUC 0.99·재현율 96%, YOLO(test3) mAP50 0.703 | 신규 슬라이드로 추가 (Ⅳ-1) |
| YOLO 모델 버전 | (미기재) | test5→**test3**로 8/15 교체(학습 유출 **확정**으로 폐기, 야장검증 36.0%) | 최신 버전으로 통일 — test5 언급 있으면 전부 test3로 교체 |

## 5. 예상 질문 대비 (전문가 심사위원 대상)

| 예상 질문 | 답변 방향 |
|---|---|
| "mAP 0.7 수준이면 실무에 바로 쓸 수 있나?" | 클래스별 편차가 크다는 것을 인정하고, YOLO가 약한 종류는 필터(24종 학습)가 이름을 보완하는 병렬 구조로 커버한다고 답변 — 아키텍처 슬라이드와 자연스럽게 연결 |
| "생성형 AI에서 왜 YOLO로 바꿨나?" | Ⅰ-2 "추진 경과" 슬라이드에서 이미 답한 내용 — 저비용 검증 → 본격 구축의 자연스러운 확장이라고 재확인 |
| "Colab 무료 GPU에 의존한다는데 안정적인가?" | 로컬 CPU 추론 경로(`serve_web_cpu.py`)를 이미 확보해 인터넷 의존을 낮췄고, 향후 자체 GPU 인프라로 이중화할 계획이라고 답변 |
| "필터의 실제 현장 정확도는?" | 정직하게: 검증 데이터셋 기준으로는 AUC 0.99·재현율 96%로 높다. **연속 실영상에서의 검증(베타테스트)은 다음 단계로 예정**돼 있고, 그 전까지는 YOLO가 함께 판독해 리스크를 낮췄다고 답변. (묻지 않으면 "잘라놓은 사진 판" 단서를 먼저 꺼내지 않아도 됨 — 질문 오면 정직하게) |
| "타 부서·기관 확산 시 데이터는 어떻게 되나?" | 관로 정보(위치·GPS 등) 학습데이터는 보안처리 후 사용하며, 로컬 모델 구조라 인터넷 미의존 환경에서도 배포 가능 |
