# 필터(C) + test3 병렬 구조 확정 — 성능 실측 전체 정리

**작성** 2026-08-15 · **브랜치** `feat/stage1-classifier`

이 문서로 모델 개발을 마감한다. 배포 구조는 **분류기(C) + YOLO(test3) 병렬**로
확정. 아래는 이 구조에 도달하기까지 실측한 모든 성능 수치를 모집단·조건과
함께 빠짐없이 정리한 것이다.

---

## 1. 확정된 구조

```
프레임 → 분류기(C) 1회 실행 ─┬─ 결함 확률  → 상위 20%가 표의 행이 된다
                            └─ 이름(확신 0.9↑) ─┐
        YOLO(test3, 16종) ──── 이름 + 박스 ──────┤→ 후보로 나란히
        LLM (선택, 기본 꺼짐) ── 이름 ────────────┘
```

- **필터와 이름 붙이기를 분류기(C) 하나가 겸한다.** 24클래스 확률 중
  `normal` 계열이 아닐 확률이 결함 점수, 최댓값이 이름.
- **YOLO는 test3로 교체했다** (기존 test5 → test3). 근거는 §4.
  기존 test5 가중치는 `apps/AI_CCTV/assets/best_test5.pt`로 보존.
- 분류기 점수 0.10 미만 프레임의 YOLO 검출은 버린다 (관 밖 오탐 방지, §3.4).
- 분류기가 없으면 옛 이진 필터(`filter.onnx`, v3)로 자동 폴백.

**모델 파일**
| 역할 | 파일 | 원본 |
|---|---|---|
| 필터+이름(다중클래스) | `apps/AI_CCTV/assets/classifier.onnx` | `C_eff_mc/best_acc.pt` |
| 검출(이름+박스) | `apps/AI_CCTV/assets/best.pt` | test3 `test3_960_e50/weights/best.pt` |
| 옛 필터(폴백용) | `apps/AI_CCTV/assets/filter.onnx` | v3 이진 |

## 2. 검증에 쓴 모집단 — 반드시 구분해서 읽을 것

같은 "결함코드"라도 **어느 판에서 쟀는지에 따라 값이 3배까지 벌어진다.**
이게 이번 작업에서 가장 중요하게 확인한 사실이다.

| 판 이름 | 결함 구성 | 정상 구성 | 학습 유출 여부 |
|---|---|---|---|
| `testset_bycode` | 455장, 23종(ETC 제외) 각 20장 — **S20/S22+AIHub만** | 200장 (IN 20%/PJ 60%/OUT_* 20%) | 분류기 학습(`clsdata_old_v6`)과 안 겹침(확인됨) |
| `valset_bycode` | 234장, 24종 각 10장 — **야장 78% + S20/S22 22%** | 233장 | 분류기와 안 겹침 |
| `test3_holdout` (신규) | 492장, 16종 각 20장(3종만 부족) — **야장 80%+S20/AIHub 20%** | 200장(PJ/IN) | test3 학습분(train+val+test 전부) 결정적 재현 후 제외 — **유출 없음 확정** |

**`testset_bycode`로 잰 YOLO 이름 정확도는 신뢰할 수 없다.** test5를
이 판으로 재면 90.0%가 나왔는데, 같은 종류를 야장 기준으로 다시 재니
33.3%로 떨어졌다(§4.1). test5의 실제 학습 파일 목록이 워크스테이션에만
있어 유출을 확정도 반증도 못 했다 — 그래서 test3로 바꾸며 재현 가능한
검증셋(`test3_holdout`)을 새로 만들었다.

## 4. YOLO 성능 — test5 vs test3, 야장 기준

### 4.1 test5 (교체 전 배포본, 17종) — 유출 의심

| 판 | YOLO 아는 종류 이름 정확도 |
|---|---|
| testset_bycode (S20/AIHub만) | 90.0% ← **유출 의심, 참고용** |
| valset_bycode 중 야장만 | **33.3%** ← 신뢰 값 |
| valset_bycode 전체(234장, 야장78%) | 22.5% |

종류별 야장 기준 재현율 (test5): SD 60%·LP 70%·BK 50%·JF 50%·CL 60%·
DS 40%·JD 20%·LS 20%·CC 20%·CM 10%·JS 10%·SG 0%. (HL은 야장 3장뿐이라
표본 부족.)

**유출 의심 근거:** test5는 서울시(S20/S22)+AIHub 풀에서 시드 고정 셔플로
train/val/test를 나눴다(`scripts/sweep/collect_dataset.py::deterministic_pick`).
`testset_bycode`는 분류기 학습분(`clsdata_old_v3`)만 제외했을 뿐 test5의
실제 train 목록은 모른다 — 그 목록이 워크스테이션에만 있어 이 세션에서
대조 불가능. testset_bycode 결함의 상당수(BK 19/20, SD 19/20 등 AIHub
비중 90%+)가 test5가 학습 때 실제로 본 파일일 가능성이 있다.

### 4.2 test3 (교체 후 배포본, 16종) — 유출 없음, 최종 채택

**`test3_holdout`**(492장, 야장 80%)으로 검증. 이 판은 test3가
train+val+test에 실제로 쓴 파일을 `deterministic_pick`(시드 42)으로
그대로 재현해 전부 제외하고 만들어 **유출이 구조적으로 불가능**하다.

| | 값 |
|---|---|
| 전체(야장) 재현율 | **105/292 = 36.0%** |
| 정상(PJ, 야장) 오탐 | 13/100 = 13.0% |
| 정상(IN, S20/AIHub) 오탐 | 0/100 = 0.0% |

결함코드별 (야장 기준, 장수는 대부분 20장 — HL 3·RT 19·SG 10만 부족):

| 코드 | 재현율 |
|---|---|
| CL | 85% |
| LP, TO | 80% |
| SD | 70% |
| BK | 50% |
| CC | 45% |
| DS | 40% |
| JF | 35% |
| LS | 30% |
| JD | 10% |
| CM, HL*, JS, PO, RT*, SG* | 0% (*표본 10장 이하) |

**test3에 없는 6종** (BC·DE·DF·DG·IF·LD): test3_18class.yaml에 클래스
자체가 없다 — "0%"가 아니라 "표본없음"으로 구분해야 한다. 이 6종은
분류기(§3)가 유일한 판독자다.

**test3 선택 근거:** test5(야장 22.5~33.3%) 대비 test3(야장 36.0%)가
확실히 높고, 유출 걱정 없는 값이라는 점에서 신뢰도도 더 높다.
mAP50도 참고치로 test3 0.703 > test5 0.698 (test5는 워크스테이션 기록
기준, 직접 재현은 안 함).

## 5. 병렬(분류기+YOLO) 합산 성능

**주의: 이 섹션은 test5로 측정했다.** test3로 다시 합산 채점은 하지
않았다(시간 관계상 이번 세션에서 생략) — 아래 수치는 "병렬 구조 자체의
이득"을 보여주는 참고 자료로 읽을 것. test3 기준 실측치가 필요하면
`scripts/classifier/score_deployed_full.py`를 재실행할 것.

### 5.1 testset_bycode(455장, S20/AIHub) 기준 — test5로 측정, 유출 의심 있음

| | 분자/분모 | 값 |
|---|---|---|
| YOLO 단독 | 234/455 | 51.4% |
| 분류기 단독 | 219/455 | 48.1% |
| **합침** | **377/455** | **82.9%** |
| 아무도 못 붙임 | 8/455 | 1.8% |

YOLO 아는 17종(260장) vs 모르는 9종(195장):

| | YOLO 아는 17종 | YOLO 모르는 9종 |
|---|---|---|
| YOLO | 90.0% | 0% |
| 분류기 | 31.2% | 70.8% |
| 합침 | 91.9% | 70.8% |

### 5.2 사진 단위 겹침 분석 (testset_bycode, 결함 455장)

| | 장수 | 비율 |
|---|---|---|
| 둘 다 맞음 | 76장 | 16.7% |
| YOLO만 맞음 | 158장 | 34.7% |
| 분류기만 맞음 | 143장 | 31.4% |
| 둘 다 틀림 | 78장 | 17.1% |

맞힌 377장 중 겹치는 건 76장(20.2%)뿐 — 두 모델이 상당히 다른 사진을
맞힌다. 다만 YOLO가 아는 17종(260장)만 보면 분류기 단독 기여는 5장(1.9%)
뿐이고, 나머지 겹치지 않는 이득은 대부분 YOLO가 모르는 9종에서 나온다.

**해석 시 주의:** 이 겹침 분석도 test5 기준이라, test5의 90.0%가
유출 영향을 받았다면 "YOLO가 아는 종류에서 거의 다 해낸다"는 결론도
과장됐을 수 있다. test3(야장 36.0%)로 다시 겹침을 재면 분류기의
기여도가 이보다 커질 가능성이 있다.

### 5.3 정상 오탐 (200장, test5+분류기 병렬, 수정 전)

| 정상 종류 | 분류기 | YOLO(수정 전) |
|---|---|---|
| IN | 0% | 0% |
| PJ | 0% | 0% |
| OUT_MH | 0% | 89% |
| OUT_CAR | 0% | 82% |

## 7. 확정 사항 요약

- **배포 구조**: 분류기(C, `classifier.onnx`) + YOLO(test3, `best.pt`) 병렬,
  분류기가 필터·1차 이름·YOLO 관밖오탐 차단을 겸함.
- **필터 신뢰도**: AUC 0.99, 결함 재현율 96%(오탐 5%) — 높음, 두 판에서
  일관됨(testset 0.9906 / valset 0.9856).
- **YOLO 신뢰도**: test3 야장 기준 36.0% — test5(22.5~33.3%)보다 낫고
  유출 걱정 없는 값. 여전히 낮은 편이나 이게 현재 데이터로 낼 수 있는
  실측 상한.
- **병렬 합산 수치(82.9%, 91.9% 등)는 test5로 측정한 것**이라 참고치로만
  볼 것 — 정확한 재측정은 후속 과제로 남긴다.
- 이 세션을 끝으로 모델 재학습·신규 실험은 진행하지 않는다. 실영상
  베타테스트가 다음 단계.

## 8. 후속 과제 (참고용, 이번엔 진행 안 함)
