## 1. 파이프에셋 야장 PDF

### 원본 분석

`C:\...\2.2. 노후관로 정밀조사 성과품-CCTV조사 야장`의 실물 PDF 3개(190~270MB, 760페이지)를
PyMuPDF로 뜯어 레이아웃을 파악했다.

```
┌─────────────────────────────────────┐
│        하수관거 현황 조사 보고서       │  제목
├─────────────────────────────────────┤
│  사업명 / 보고서번호 / 관로 / 맨홀 …   │  메타데이터 표 (약 20항목)
├──────┬──────────────────────────────┤
│ 관로  │  사진   사진                  │  좌: 관로 모식도(거리 눈금)
│ 모식도│  사진   사진                  │  우: 사진 2열 × 3행 = 6장
│      │  사진   사진                  │     각 사진 아래 캡션
├──────┴──────────────────────────────┤
│ 보고서번호:… / 관로번호:… - (n)  조사자 │  꼬리말
└─────────────────────────────────────┘
```

관로가 바뀌면 페이지 번호가 `(1)`부터 다시 시작한다. 캡션 322건을 분석해 표기 규칙도 맞췄다.

### 구현 시 판단한 것

- **결함명 표기** — 야장은 하이픈이 없다(`균열-원주` → `균열원주`). `config.DEFECT_PIPEASSET`에
  별도 매핑을 두고, `PJ(이음부 정상)`처럼 결함이 아닌 항목은 `(상태)`로 분류했다
- **사진 비율 유지** — 조사 사진은 증빙이라 셀에 맞춰 늘이면 안 된다. 남는 여백은 회색으로 채운다
- **연결선 우회** — 오른쪽 열 사진으로 가는 선이 왼쪽 사진을 가로질러서, 행 사이 여백으로 돌렸다
- **등급 편집 분리** — 표시는 `BK(파손)`이지만 편집하면 코드(`BK`)만 나온다. 표시 문구를 그대로
  고치게 두면 `BK(파손)` 전체가 결함 코드로 저장된다

엑셀은 그대로 두고 [보고서 출력]에서 형식을 고르게 했다.

## 2. 세션 영속화 — 재시작해도 결과 유지

**증상** — 코드를 고쳐 서버를 재시작하면 몇 십 분 걸린 분석 결과가 사라진다.

**원인** — 프레임 이미지와 상태를 모두 `tempfile.mkdtemp()`에 두고 있었다. 이 폴더는 서버를
켤 때마다 새로 만들어지고 OS가 청소하기도 한다. 결과가 메모리에서 사라질 뿐 아니라 **사진까지
함께 없어졌다.**

**조치** — 저장 위치를 고정 폴더(`%LOCALAPPDATA%\AI_CCTV\`)로 옮기고 결과를 JSON으로 저장한다.

```
AI_CCTV/
├── session.json   ← 분석 결과·편집 내용·보고서 정보
├── frames/        ← 프레임 이미지
└── uploads/       ← 업로드한 영상
```

분석 중 영상 하나가 끝날 때마다, 그리고 편집·설정 변경마다 저장한다. 임시파일에 쓰고 교체하므로
저장 도중 죽어도 기존 파일이 깨지지 않는다. `AI_CCTV_DATA_DIR`로 위치를 바꿀 수 있다.

## 3. 자막에서 보고서 정보 자동 입력

CCTV 오버레이에서 8종을 새로 읽는다.

| 자막 | 읽는 값 |
|---|---|
| `# SD-A04-006` / `# SD-A04-007` | 상류·하류 맨홀번호 |
| 우상단 `2023-06-13` | 조사일자 |
| `Φ 200 / PVC / 오수` | 관종, 배수방식 |
| 하단 `정주행` | 주행방향 |
| `위도 : 37.79…` / `경도 : 127.31…` | 위도, 경도 |

OCR이 흔히 틀리는 경우까지 처리했다 — `#`을 `±`/`＃`로, `0`을 `O`로, `오수`를 `요수`로 읽는 경우.
위경도 라벨을 못 읽으면 한국 좌표 범위(위도 33~39·경도 124~132)로 구분한다.

**총주행거리**는 마지막 프레임 거리로 잡고 `연장`에 같은 값, `미주행거리`는 `0.0m`을 넣는다.

**이미 입력된 값은 덮어쓰지 않는다.** 검수해서 고친 값이 재분석 때 OCR 결과로 되돌아가면 안 된다.

## 4. 보고서 정보를 관로별로 분리

**증상** — 영상이 여러 개일 때 두 번째 영상부터 맨홀번호·관종이 무시된다.

**원인** — `report_meta`가 전체 공통 1세트였다. "이미 채워진 값은 덮어쓰지 않는다" 규칙 때문에
첫 영상 값만 남았다. 관로마다 맨홀번호가 다르므로 실사용에서 바로 문제가 된다.

**조치** — 항목을 두 갈래로 나눴다.

| 구분 | 개수 | 항목 |
|---|--:|---|
| 현장 공통 | 8 | 발주처·사업기간·처리구역·배수구역·배수분구·시공자·조사목적·조사자 |
| 관로별 | 25 | 보고서번호·조사위치·조사일자·관종·배수방식·주행방향·연장·총주행거리·미주행거리·위경도·맨홀 전체·상태등급 전체·미주행사유 |

보고서 정보 창에 관로 선택 드롭다운을 넣고, 공통 항목은 라벨 색으로 구분했다. OCR 자동 입력과
거리 계산도 영상별로 돌아간다.

> 저장 형식이 바뀌어 세션 스키마를 `1 → 2`로 올렸다. 예전 세션은 건너뛰고 새로 시작한다.

## 5. 그 외

- **조사 시작지점 탐색 OFF** — `try_ocr_find_range`가 영상당 OCR을 최대 15번 더 돌리는데,
  못 찾으면 어차피 0초부터 본다. 기본으로 껐고 `OCR_FIND_START=1`로 되살릴 수 있다
- **`tools/seed_demo.py`** — 추론 없이 보고서만 확인하는 샘플 데이터 생성기. Colab이 죽었거나
  로컬에 모델(`assets/best.pt`)이 없을 때 쓴다. 실제 영상을 주면 그 프레임으로 채운다
- **한글 경로 버그** — `cv2.imwrite`가 경로에 한글이 있으면 **조용히 실패한다**(파일이 안 생기고
  에러도 없음). 폴더명이 `샘플영상`이라 프레임이 하나도 안 만들어졌는데, PDF는 폰트 임베딩 탓에
  7.4MB로 정상처럼 보였다. `imencode` + `tofile`로 교체
- **현장명 오염** — 주행방향이 현장명 바로 아래에 있어 `가평군 현리사유 정주행`으로 읽혔다
- `pymupdf`를 `requirements.txt`에 추가
