# 작업 보고서

git push 단위로 남기는 작업 기록. 커밋 메시지에는 담기지 않는 **증상 / 원인 / 조치**와
검증 결과를 남긴다 — 보고된 증상과 실제 원인이 다른 경우가 잦아서, 나중에 같은 문제를
다시 만났을 때 이 기록이 커밋 로그보다 빠르다.

| 일자 | 보고서 | 커밋 |
|---|---|---|
| 2026-07-31 | [웹 데모 개선](2026-07-31-웹데모-개선.md) — 업로드/다운로드 실사용화, Colab 연결 진단, 결과표 개편 | `dfc0598` |

## 작성 규칙

- 파일명 `YYYY-MM-DD-<주제>.md`
- 구성: 요약 수치 → 요청 처리 → 확인 중 발견한 문제 → 검증 → 반영 → 남은 과제
- 항목은 **증상 / 원인 / 조치** 3단으로 쓴다
- 검증 수치는 실제로 돌린 결과만 적는다(추정치 금지)
- 잘못 짚었던 것도 적는다 — 테스트가 틀려 멀쩡한 기능을 실패로 판정한 경우 등
