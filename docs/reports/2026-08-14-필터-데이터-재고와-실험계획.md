## 요약

실영상 AUC 0.52(→ 폐기됨, 위 참고)를 어떻게 올릴지 두 갈래로 시도했다.

| 시도 | 결과 |
|---|---|
| **① 흑백 학습** — 색조 차이가 원인인가 | **기각.** 0.5205 → 0.5259 (잡음) — *실영상 비교는 무효, 야장 val 0.9503→0.9517로 기각 판단은 유지* |
| **② 영상 정상 보강** — 평범한 구간이 없는 게 원인인가 | `clsdata_old_v4` 구성 완료, 학습 대기 |

그리고 **지금까지 쓴 데이터를 전부 훑었다.** 그 과정에서 두 가지가 드러났다.

- **연속 영상에서 뽑은 정상 1,058장이 이미 있었다**(`clsdata_v2`). A~E 실험이 그것만으로
  학습해 양이 부족했고, OLD 계열은 그것이 아예 없었다. **둘을 합친 조합은 없었다.**
- **현장 간 일반화를 한 번도 재본 적이 없다.** val이 train과 같은 3개 현장이다.

## 1. 흑백 실험 — 기각

### 근거는 있었다

학습 데이터와 실영상의 색조가 계통적으로 다르다.

| 집합 | R−B (파란 기운) | 채도 |
|---|---|---|
| 야장 (학습) | −16.4 | 0.136 |
| AIHub (학습) | **−27.2** | **0.242** |
| SM2 실영상 | −7.5 | 0.090 |
| JB 실영상 | −3.9 | 0.121 |

학습 데이터가 실영상보다 확연히 푸르고 진하다. AIHub는 채도가 실영상의 2배다.
모델이 결함의 생김새 대신 이 색조를 학습했다면 실영상에서 무너지는 것이 설명된다.

### 결과

`train_binary.py --gray`로 같은 데이터(`clsdata_old_v3`)를 흑백으로 다시 학습했다.
학습 경로 `Grayscale(3)`와 추론 경로 `convert("L").convert("RGB")`가 픽셀 단위로
같은 것을 먼저 확인했다(최대 차이 0).

| | 야장 val AUC | **실영상 AUC** | 상위 20% 유실 |
|---|---|---|---|
| 컬러 OLD_v3 | 0.9503 | **0.5205** | 0/13 |
| 흑백 epoch 9 (best) | **0.9517** | **0.5259** | 1/13 |
| 흑백 epoch 23 (last) | 0.9463 | **0.4635** | 3/13 |

**색을 완전히 지웠는데 야장 val이 그대로다**(0.9503 → 0.9517). 색이 val 성적의
근거가 아니었다는 뜻이고, 실영상도 움직이지 않았다.

epoch 23은 **0.4635로 무작위보다 못하다.** 확률 중앙값이 결함 0.9671 / 그 외 0.9681로
완전히 붙었다 — 오래 학습할수록 야장에 특화되면서 실영상에서는 전부 "결함"이라
부르는 쪽으로 갔다.

### 부수적으로 확인한 것

정점 epoch이 컬러 때보다 늦어졌다(2~6 → 9). 색이라는 단서를 뺏으니 배울 것이 더
남아 있었다는 뜻이다. 다만 그렇게 배운 것도 실영상으로는 옮겨가지 않았다.

임계값 표가 컬러와 거의 같은 자리에 떨어진 것도 눈에 띈다 — 컬러 `0.0320 → 23.6% 제거`,
흑백 `0.032 → 23.5% 제거`. 색을 빼도 모델이 같은 곳에 착지했다.

## 2. 학습 데이터 재고

원천은 여섯 갈래다. 지금까지의 모든 실험은 이것을 조합한 것뿐이다.

| # | 원천 | 정상 | 결함 | 성격 |
|---|---|---|---|---|
| **①** | AIHub | IN 4,000 · PJ 3,000 | 9종 3,000 | 정지 이미지. 색조·화면구성이 현장과 다름 |
| **②** | S20/S22 | **없음** | 24종 4,831 | 결함 유형 보강용. 정상이 없어 단독 불가 |
| **③** | 야장 PDF (북면·상면·설악면) | 6,744 | 5,307 | 조사원 판정. **기록된 순간만** |
| **④** | 상면 CCTV 영상 (SM1/SM2) | 1,058 | 590 | **연속 영상.** 평범한 구간이 있다 |
| **⑤** | fieldset (현리산유 등 신설 오수) | 123 | 175 | 신설관로. 하자목록 기준 |
| **⑥** | 한글 조사표 | — | 거리 목록 | 라벨 소스 (프레임이 아님) |

**④만 유일하게 "평범한 구간"을 갖고 있다.** ①②③⑤는 전부 누군가 골라낸 순간이다.

③의 정상 6,744장 중 89%가 `이음부(접합부)존재`다. 나머지는 `연결관존재함` 693,
`관종변경` 35, `치수변화` 25. 아무것도 없는 밋밋한 관 내부는 한 장도 없다.

  한글 조사표의 결함 위치에서 일정 거리 이상 떨어진 구간을 정상으로 삼는다.

## 4. 가장 큰 구멍 — 현장 간 검증이 없다

```
train 현장: 북면, 상면, 설악면 (+aihub, s20)
val   현장: 북면, 상면, 설악면      ← 같은 현장
관로:  train 287개 / val 71개 · 겹침 0개
```

관로는 겹치지 않지만 **현장은 완전히 같다.** 지금까지 잰 것은 "같은 현장의 다른
관로에서 되는가"이고, **"새 현장에서 되는가"는 한 번도 재본 적이 없다.**

야장 val 0.95와 실영상 0.52의 간극이 여기서 나온다. 실영상 측정이 사실상 첫
현장 간 검증이었던 셈이다.

## 5. OLD_v4 — 야장 + 영상 정상

안 해본 조합 중 첫 번째를 만들었다(`build_old_v4.py`).

| | OLD_v3 | **OLD_v4** |
|---|---|---|
| train 정상 | 12,313 | **14,983** |
| — 그중 영상 프레임 | **0** | **2,670** (890장 × 3배, 17.8%) |
| train 결함 | 11,989 | 12,514 |
| val | 2,580 | **2,580 — 파일명까지 동일** |

### 관로 누수를 막는 것이 핵심이었다

영상과 야장은 **같은 관로를 다른 방식으로 담고 있다.** 상면 CCTV의
`SM1-131-001/6058.mp4`는 야장 관로 6058과 같은 관이다. 관로번호로 대조해
`clsdata_old_v3`의 split을 그대로 따라가게 했고, old_v3에서 val인 관로
(**6058·6085**)의 영상 프레임 233장은 버렸다. train에 넣으면 누수이고,
val에 넣으면 OLD_v3와의 비교가 깨진다.

val을 손대지 않은 것은 의도적이다. AUC를 0.9503과 직접 비교할 수 있어야 한다.
판정은 어차피 실영상(`score_on_real_video.py`)으로 한다.

890장은 train 정상의 7%뿐이라 그냥 넣으면 묻힌다. 3배로 복제해 17.8%로 올렸다.

## 6. 실험 계획

**새 현장 자료의 가장 큰 값어치는 학습 데이터가 아니라 정직한 val이다.**

### 받을 때 확인할 것

| 항목 | 왜 |
|---|---|
| **영상 원본** | 없으면 ④를 못 만든다. 조사표만 오면 ③ 종류만 늘어난다 |
| **야장(PDF)인가 하자목록(HWP)인가** | 야장은 정상 기록도 있어 훨씬 낫다 |
| 신설 / 노후 | 신설이면 신설 필터가 처음으로 가능해진다 |
| 관로번호 ↔ 영상 파일명 매칭 | 안 되면 자동 추출이 안 된다 |

### 순서

**E0. OLD_v4_gray_video** (학습 대기)
③+①+②+④ 흑백. 영상 정상 890장(×3)의 효과만 본다.
→ 실영상 0.52에서 움직이는지가 전부. 안 움직이면 890장이 부족하다는 근거가 된다.

**E1. 새 현장에 기존 모델을 그냥 돌린다** ← 최우선. 학습 없이 채점만.
→ **현장 간 일반화를 처음으로 정직하게 재는 것.** 실영상 0.52가 "필터가 나쁘다"인지
"새 현장이라 그렇다"인지 갈린다. 30분이면 답이 나온다.

**E2. 새 현장 영상에서 영상 정상 추출 → 양 늘리기**
E0이 조금이라도 움직였다면 여기로. `extract_ordinary_normals.py`(야장 기준)를 쓴다.
기존 ④는 한글 조사표(결함만) 기준이라 성긴데, 야장 기준이면 10.3초에 1건으로
훨씬 엄격하다.

**E3. AIHub 빼기 (③+④만)**
①은 7,000장으로 정상의 절반을 차지하는데 도메인이 다르다. 오염일 수 있다.
싸고 빠른 A/B.

### 예측

| 조합 | 예상 실영상 AUC | 근거 |
|---|---|---|
| E0 (영상 정상 890×3) | 0.55 ~ 0.62 | 종류는 맞는데 양이 적다 |
| **E2 (영상 정상 수천 장)** | **0.65 ~ 0.75** | 없던 칸이 제대로 채워진다 |
| E3 (AIHub 제거) | ±0.03 | 크게 안 움직일 것 |
| 흑백 | — | 이미 기각 |

**가장 승산 있는 조합은 ③+④(대량).** ③이 결함 유형과 판정 품질을 주고 ④가
"평범함"의 기준을 주는 구조라 서로 보완된다. ①②는 있으나 없으나일 가능성이 높다.

미리 각오할 것 — **새 현장을 val로 붙이면 지금 숫자들이 다 내려간다.** 0.95가
0.7대로 보일 수 있다. 그것이 나쁜 게 아니라 처음으로 정직한 숫자를 보는 것이다.

## 7. 이번에 추가된 도구

| 파일 | 역할 |
|---|---|
| `train_binary.py --gray` | 흑백 학습. 체크포인트에 `gray`를 기록해 배포 때 확인 |
| `backend/config.py FILTER_GRAYSCALE` | 추론도 흑백으로. 학습과 어긋나면 측정이 무너진다 |
| `score_on_real_video.py` | 후보를 **실영상**으로 채점. 무작위 대조군을 항상 같이 찍는다 |
| `build_old_v4.py` | 야장 + 영상 정상. 관로 단위 누수 방지 |
| `extract_ordinary_normals.py` | 야장이 침묵한 시각을 정상으로 추출 (E2용, 미실행) |
