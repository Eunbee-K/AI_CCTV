| | 8/11 저녁 | 8/12 |
|---|---|---|

## 1. 8/11 결론이 왜 틀렸나

두 가지가 겹쳐 있었다.

### ① 측정 코드가 앱과 다른 그림을 넣고 있었다

`eval_series_vs_parallel.py`는 원본 16:9 프레임을 `Resize(224)+CenterCrop(224)`로
넣었다. 학습 데이터는 프레임을 **256×256으로 찌그러뜨려** 저장한 것이라
(`build_binary_dataset.py`), 좌우가 잘린 **모델이 본 적 없는 입력**이었다.

배포본이 망가진 건 아닌지부터 갈랐다 — 야장 val 2,580장에서 ONNX가
**AUC 0.9503을 정확히 재현**했다. 모델도 변환도 정상이다.

### ② 무작위 대조군이 없었다

| 상위 20%로 자를 때 | 사라진 결함 |
|---|---|
| 필터 | 0 / 13건 |
| **무작위 (1,000회 평균)** | **0.4 / 13건** |

결함 하나가 프레임 수십 장에 걸쳐 있으면 아무 프레임이나 20% 골라도 살아남는다.
정답 구간이 전체의 24.6%(한 관로는 100%)였으니 당연한 결과였다.

### 실제 성능

| | 야장 val 2,580장 | SM2 실영상 1,014장 |
|---|---|---|
| 결함 확률 중앙값 | 0.9412 | 0.9420 |
| 정상 / 그 외 중앙값 | **0.0370** | **0.9380** |
| AUC | **0.9503** | **0.5205** |

**갈라지지 않는다.** v1(AIHub 78,388장)이 현장에서 0.516이었을 때와 같은 모양이다.

원인은 학습 데이터의 성격이다. 야장의 정상과 결함은 **둘 다 조사원이 기록할 만하다고
판단한 순간**이고, 그 사이를 흐르는 평범한 구간은 아예 없다. 실제 영상은 대부분이
그 구간이라 프레임의 54.7%가 확률 0.9 이상으로 나온다.

## 2. lead — 행을 만드는 주체를 바꿨다

```
프레임 1초 간격 추출
        ↓
   Stage-1 필터  ──→  결함 있는 구간을 고른다 (표의 행이 된다)
        ↓
      YOLO       ──→  그 구간에 이름 + 박스를 붙인다
        ↓
      LLM(선택)  ──→  같은 구간에 이름을 덧붙인다. 박스는 없다
```

지금까지는 YOLO가 박스를 친 프레임만 행이 됐고 필터는 옆에서 훈수만 뒀다.
이제 필터가 고른 구간이 먼저 행이 되고 YOLO 검출은 거기에 얹힌다.
**YOLO가 아무것도 못 찾은 구간도 행으로 남아** 검수자가 직접 판단한다.

설계에서 신경 쓴 것:

- **절대 임계값을 쓰지 않는다.** 0.032로 자르면 실영상 프레임의 99.4%가 통과한다.
  영상 안에서의 순위(상위 20%)로 자른다.
- **이어진 프레임은 한 구간으로 묶는다.** 결함 하나가 열 줄로 늘어나지 않게.
- **대표 프레임은 YOLO가 가장 자신 있게 검출한 것.** 박스가 보여야 판단할 수 있다.
- **필터가 안 고른 곳의 YOLO/LLM 검출은 로그에 남긴다.** 표에는 안 넣지만
  조용히 사라지지도 않는다. 이 숫자가 크면 상위 비율을 올려야 한다는 뜻이다.

### 실주행 — SM2-144-001 (2:54, 노후)

YOLO 검출 42개가 **7행**으로 압축됐고, 조사표 결함 **5.4m·7.5m가 둘 다 들어왔다.**

```
00:22  000.0m  OBST        01:58  005.4m  JS
01:24  002.5m  OBST        02:06  005.4m  JS
01:32  003.1m  JD, JF      02:28  007.5m  CL
01:38  003.1m  JD
```

## 3. YOLO를 test5(17종)로 교체

test6(12종)에 **균열 클래스가 아예 없던 것**이 "너무 못 잡는다"의 실체였다.

| | test6 | test5 |
|---|---|---|
| 클래스 | 12종 | **17종** |
| 전체 mAP50 | 0.791 | 0.698 |
| 추가되는 것 | — | CC·CL·CM(균열) · HL(천공) · JF·JS(이음부) · SD(표면손상) · DF(변형) |

같은 노후 영상(SM2-144-001, 88프레임)에서:

| | test6 | test5 |
|---|---|---|
| 검출된 프레임 | 27 (31%) | **45 (51%)** |
| 박스 | 30 | **50** |

균열-길이만 14개가 새로 잡힌다. **전체 mAP는 떨어지지만 잡는 종류가 는다** —
조사표를 채우는 게 목적이므로 이쪽이 낫다.

`test5`는 변형 클래스명을 `DF`가 아니라 `DEFORM`으로 학습했다. `YOLO_CLASS_MAP`에
별칭을 둬 코드표에 맞췄다. 이전 모델은 `assets/best_test6.pt`로 남겨뒀다.

## 4. LLM 판독 — 세 번째 의견

ver_2.2 앱(`<드라이브>:/CCTV/ver_2.2_AICCTV`)의 Gemini+GPT 구조를 옮겨왔다.
그쪽은 LLM이 분석의 전부였지만 여기서는 **이름을 붙이는 자리에만** 선다.

**회사망에서는 못 쓴다.** 외부 API를 부르므로 기본이 꺼짐이고 앱 화면에서 켠다.
꺼져 있으면 패키지가 없어도 정상 동작한다.

옮기면서 고친 것:

- **두 모델 모두에게** 예시 사진을 보낸다. ver_2.2는 GPT에만 보냈다.
- 라벨을 `labels.jsonl`에서 읽는다. 파일명 부분일치는 복합 라벨이 잘못 걸린다.
- **정상 사진도 보낸다.** 예시 없이 돌리면 88프레임 중 69장을 결함이라 본다.
  정상 예시를 넣으니 58장으로 줄었다.
- 청크를 하나씩 기다리지 않고 한 번에 던진다. **456초 → 133초.**
- API 키는 서버 메모리에만 둔다. ver_2.2는 `api_keys.jsonl`로 저장했는데,
  이 앱은 세션 파일로 결과를 주고받으므로 키가 딸려 나간다.

UI는 한 줄(49px)만 두고 설정은 창에서 받는다 — 쓰는 사람이 많지 않은데 사이드바를
크게 차지하고 있었다.

## 5. 프레임 간격 2초 → 1초

`JB1-2-0413`의 2:31 결함(13.5m)이 표에 안 나오던 원인이 셋이었다.

**① 2초 간격이 결함을 건너뛴다.**

| | 2초 | 1초 |
|---|---|---|
| 프레임 | 128장 | 256장 |
| 최대 점프 | **0.60m** | 0.30m |
| 2:31 결함 | 탈락 | **통과** |

**② 필터 구간과 YOLO 검출이 한 프레임씩 어긋난다.** 필터는 02:33 한 장만 골랐는데
YOLO는 02:32와 02:34를 잡아 딱 사이로 빠졌다. 구간에 내부 검출이 없을 때만
±`FRAME_INTERVAL` 밖까지 찾아 같은 결함으로 본다.

**③ 대표 프레임 선정이 신뢰도를 못 읽고 있었다.** 박스의 키가 `confidence`인데
`conf`로 읽어 항상 0이었다.

셋을 고치고 나서:

```
01:55  010.5m  JD(이음부-단차)   ← 1:47 변형 (10.1m)
02:32  013.7m  JD(이음부-단차)   ← 2:31 변형 (13.5m)
```

**위치는 잡고 이름은 틀린다.** 변형이 아니라 이음부-단차로 붙는다.

## 6. 신설 / 노후

**지금은 갈라지지 않는다.** 둘 다 같은 필터·같은 YOLO·같은 설정으로 돈다.
`state.pipe_condition`은 분석 전에 뭐라도 골랐는지만 확인하고, 그 값으로 분기하는
코드는 한 군데도 없다.

신설 전용으로 만든 것은 아무것도 쓰이지 않는다 — 필터 NEW_v1은 AUC 0.7466으로
미달이고, fieldset으로 파인튜닝할 YOLO는 아직 없다.

가를 자리는 세 군데다: **필터 모델 · YOLO 모델 · 상위 컷 비율**(신설은 결함이 적어
20%가 과할 수 있다). 근거가 생기면 `state.pipe_condition`으로 분기하면 된다.

## 8. 교훈

**① 무작위 대조군 없는 "유실 0건"은 아무 말도 아니다.** 정답 구간이 전체의 24.6%면
아무 프레임이나 20% 골라도 유실이 0.4건이다. 개선을 보고하기 전에
"무작위로 해도 이 값이 나오는가"를 먼저 묻는다.

**② 측정 코드가 앱과 다른 전처리를 쓰면 잰 값이 전부 무효다.** 평가는 앱이 실제로
쓰는 경로(`backend/defect_filter.py`)를 그대로 불러 쓴다.

**③ 프레임 번호가 아니라 거리로 본다.** "결함 2건이 리스트에 없다"고 봤던 것이,
거리로 보니 카메라가 멈춰 있어서 0.4m 차이였다. 조사표가 거리로 적히므로 판정도
거리로 해야 한다.

**④ 전체 mAP가 높은 모델이 더 나은 모델이 아니다.** test6은 0.791인데 균열을 아예
못 잡는다. test5는 0.698인데 균열을 잡는다. 조사표를 채우는 게 목적이면 후자다.
