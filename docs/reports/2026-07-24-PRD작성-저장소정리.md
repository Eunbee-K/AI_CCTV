## 1. PRD 작성 (`0e62058`)

기존 코드베이스를 역으로 분석해 PRD를 작성

```
docs/PRD.md
├── 1. 배경 및 문제 정의
├── 2. 제품 개요
├── 3. 사용자 및 사용 시나리오
├── 4. 현재 구현 범위 (As-Is, 2026-07-24 기준)
│   ├── 4.1 파이프라인 (영상 입력 → 출력)
│   ├── 4.2 추론 실행 위치 (로컬 vs 원격)
│   ├── 4.3 UI / 상호작용 기능
│   ├── 4.4 데이터/상태 관리
│   ├── 4.5 기술 스택
│   └── 4.6 명시적으로 제외된 기능
├── 5. 결함 탐지 모델 — 범위와 현황 (가장 중요한 Gap)
│   ├── 5.1 배포 모델 vs UI 라벨 매핑 vs 목표 클래스 체계
│   └── 5.2 모델 실험 이력
├── 6. 비기능 요구사항 / 아키텍처 제약
├── 7. 알려진 제약 / 리스크
├── 8. 로드맵 제안 (근거: 설정 파일/실험 이력 기반 추정)
├── 9. Out of Scope (현재 버전 기준)
└── 10. 미정 사항 (TBD — 문서화되지 않아 코드에서 확인 불가)
```

**5장이 핵심이다.** "배포 모델 vs UI 라벨 매핑 vs 목표 클래스 체계"를 나란히 놓아, 실제
쓸 수 있는 것과 목표로 하는 것 사이의 간극을 코드 확인 없이도 볼 수 있게 했다. 이 프레임이
이후 08-04 실험 정리 보고서("현재 배포된 모델은 없다")까지 그대로 이어진다.

비즈니스 지표·일정처럼 코드로 확인할 수 없는 항목은 10장에 **TBD로 명시**하고 추정으로
채우지 않았다.

`.gitignore`에 Office 잠금 파일(`~$*.xlsx` 등) 규칙도 함께 추가했다 — 엑셀 문서를 다루기
시작하면서 생기는 임시 파일이 저장소에 들어가지 않도록.
