- 문서 버전: v0.1 (초안, 코드베이스 리버스엔지니어링 기반 작성)
- 작성일: 2026-07-24
- 대상: `E:\AI_CCTV_PROJECT\apps\AI_CCTV` (배포 애플리케이션) + 이를 뒷받침하는 YOLO 학습/실험 파이프라인
- 범위: **딥러닝 기반 CCTV 하수관로 결함 탐지 제품**을 다룬다. 데이터 라벨링/정리 도구, 학습 자동화 스크립트는 이 제품을 만드는 수단으로만 언급하고 상세 요구사항은 별도 문서로 다룬다.

## 1. 배경 및 문제 정의

하수관로 CCTV 조사는 현재 사람이 영상을 처음부터 끝까지 육안으로 보며 결함 구간(균열, 파손, 이음부 손상, 토사퇴적 등)을 찾아 수기로 조사보고서(엑셀)를 작성하는 방식으로 이뤄진다. 이 작업은:

- 영상 1편당 검토 시간이 길고, 검토자의 숙련도에 따라 결함 누락/오분류 편차가 크다.
- 관경·거리·관로번호 등 화면 자막(OCR 대상)을 사람이 직접 옮겨 적어야 한다.
- 결과물이 표준화된 엑셀 조사표 형태로 나와야 실무에 바로 쓸 수 있다.

**AI CCTV**는 이 과정을 YOLO 기반 딥러닝 결함 탐지 + OCR 자동 판독으로 보조/자동화하여, 검토자가 "탐지된 결과를 확인·보정"만 하면 되는 워크플로로 바꾸는 것을 목표로 한다.

## 2. 제품 개요

Windows용 **로컬 데스크톱 애플리케이션**(pywebview 네이티브 창 + FastAPI 백엔드 + JS 프론트엔드, 별도 설치형 웹서버 아님)으로, 기존 tkinter 버전(`ver3.1_AI_CCTV_YOLO`)을 대체한다.

> "하수관로 CCTV 영상에서 YOLO(`best.pt`)로 결함을 자동 탐지하고, 편집 가능한 결과표와 엑셀 보고서를 생성하는 데스크톱 앱." — 앱 README

핵심 가치 제안:
1. 영상을 큐에 넣기만 하면 결함 프레임을 자동 추출·탐지·주석 처리한다.
2. 화면 자막(거리/관경/관로번호/현장명)을 OCR로 자동 판독해 결과표에 채운다.
3. 결과를 표에서 바로 검수·수정(오탐 제외, 값 편집)하고 엑셀로 즉시 내보낸다.

## 3. 사용자 및 사용 시나리오

- **주 사용자**: 하수관로 CCTV 조사 결과를 정리하는 현장/사무 담당자 1인 (동시 다중 사용자 미고려, DB 없이 메모리 상태로 동작).
- **핵심 시나리오**:
  1. 조사 영상(mp4/avi/mkv, 여러 개) 선택 → 큐 등록
  2. 분석 실행 → 진행률(프레임 추출/YOLO/OCR 단계) 실시간 표시
  3. 결과표에서 결함별 신뢰도 임계값·클래스 필터로 검토, 플레이어에서 해당 시점으로 바로 이동해 육안 확인
  4. 오탐 체크, 값 수정(관경/거리/관로번호/결함종류/비고), 필요시 행 수동 추가/삭제
  5. "엑셀로 내보내기" → 표준 조사표(`CCTV_조사_집계표.xlsx`) 생성, 프레임 이미지 임베드

## 4. 현재 구현 범위 (As-Is, 2026-07-24 기준)

### 4.1 파이프라인 (영상 입력 → 출력)

| 단계 | 구현 위치 | 설명 |
|---|---|---|
| 1. 조사 시작점 자동 인식 | `backend/ocr.py` | 영상 앞 30초를 2초 간격으로 PaddleOCR 스캔, "조사시작/시작" 텍스트로 시작 오프셋 결정 |
| 2. 프레임 추출 | `backend/frames.py` | 시작~끝 구간 2초 간격으로 JPEG(품질 80) 추출 |
| 3. 결함 탐지 | `backend/yolo_infer.py`(로컬) / `backend/yolo_remote.py`(원격) | Ultralytics YOLO, conf 0.35 / imgsz 960, **바운딩박스 탐지만 지원 (세그멘테이션 미지원)** |
| 4. 자막 메타데이터 OCR | `backend/ocr.py` | 거리(`\d+.\d+m`)/관로번호(`XXX-YYY`)/관경(`Φ200`)/현장명 정규식 파싱 |
| 5. 중복 거리 플래깅 | `backend/rows.py` | 동일 거리값이 2회 이상 검출되면 "확인필요" 표시 (자동 삭제 아닌 인간 검수 유도) |
| 6. 주석 처리 | `backend/annotate.py` | bbox + 한글 라벨 + confidence%를 프레임에 오버레이 |
| 7. 엑셀 출력 | `backend/excel_export.py` | 주행방향/영상위치/관로번호/관경/거리/결함종류/비고 + 프레임 이미지 임베드 |

### 4.2 추론 실행 위치 (로컬 vs 원격)

- 기본값은 **원격 추론**: Google Colab GPU를 Flask 서버로 노출하고 고정 ngrok 도메인으로 터널링(`notebooks/inference_colab_server.ipynb`). 로컬 PC는 CPU만 있어도 됨(`ultralytics`/`torch` 로컬 설치 불필요).
- UI에서 "Colab 추론 서버" URL을 직접 지정 가능, 비워두면 로컬 추론(`yolo_infer.py`)으로 전환.
- 프레임을 24장씩 청크로 나눠 전송, 청크 단위 에러 격리로 GPU OOM 시 전체 실패 방지.

### 4.3 UI / 상호작용 기능

- **영상 플레이어**: MJPEG 스트리밍 재생, 0.5~2.5배속, 확대/축소·드래그 팬, bbox 실시간 오버레이, 키보드 단축키(스페이스/화살표).
- **결과표**: 영상별/중복거리 그룹별 접기, 셀 더블클릭 인라인 수정, confidence 슬라이더(0~95%) + 클래스별 토글(표·오버레이 공용 필터), 오탐 체크박스(통계·엑셀 제외), 행 수동 추가/삭제, ↑/↓ 키로 탐지 결과 간 이동(플레이어 자동 동기화).
- **통계 탭**: 영상별/전체 결함 클래스별 카운트(오탐 제외).
- **진행 상황**: WebSocket(`/ws/progress`)으로 단계별 로그·진행률·결과 실시간 push.
- **네이티브 파일 다이얼로그**: 영상 다중 선택, 엑셀 저장 경로 선택 (pywebview API, 브라우저 단독 실행 시 `prompt()`로 대체).

### 4.4 데이터/상태 관리

- 인메모리 상태만 사용 (`state.py`) — "단일 사용자 로컬 데스크톱 앱이므로 DB 없이 메모리로 관리". 앱 종료 시 미내보내기 결과는 소실.
- 세션별 임시 디렉터리에 추출 프레임 저장.
- 인증/다중 사용자/이력 관리 없음.

### 4.5 기술 스택

FastAPI + uvicorn + pywebview(데스크톱 창) + vanilla JS(빌드 스텝 없음) / Ultralytics YOLO(로컬 옵션) / PaddleOCR / OpenCV / Pillow / OpenPyXL / (원격 추론 시) Flask + pyngrok on Colab.

### 4.6 명시적으로 제외된 기능

- 이전 tkinter 버전에 있던 **GPT/Gemini 멀티모달 분석은 제거됨** ("실제 파이프라인에서 쓰이지 않던 기능이라 제외") — LLM 호출 없이 YOLO+OCR 규칙 기반 파이프라인만 사용.

## 6. 비기능 요구사항 / 아키텍처 제약

- **오프라인 내성**: 학습은 인터넷이 불안정한 워크스테이션에서도 무인 실행 가능하도록 설계(`scripts/sweep`가 별도 문서 대상, 참고만). 반면 **배포 앱의 기본 추론 경로는 인터넷(Colab+ngrok) 의존** — 상충되는 지점이며 리스크로 관리 필요(§8).
- **단일 사용자, 로컬 실행**: 서버 배포/동시접속/권한 관리 요구사항 없음(현재 설계 기준).
- **저사양 대응**: 로컬 추론은 선택 사항이며 CPU만으로도 원격 모드 구동 가능하도록 설계됨.
- **한글 처리**: bbox 라벨 한글 렌더링(PIL, CJK 폰트 미탐지 시 영문 폴백), OCR 대상도 한글 자막 포함.

| 프로젝트 관리 성숙도 | Git 이력 단일 커밋, 실험 메타데이터(`detect_v2.yaml` names 등) 일부 미기입 상태로 방치 | 낮음~중간 |

## 9. Out of Scope (현재 버전 기준)
