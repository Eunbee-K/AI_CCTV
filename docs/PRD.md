## 1. 배경 및 문제 정의

하수관로 CCTV 조사는 현재 사람이 영상을 처음부터 끝까지 육안으로 보며 결함 구간(균열, 파손, 이음부 손상, 토사퇴적 등)을 찾아 수기로 조사보고서(엑셀)를 작성하는 방식으로 이뤄진다. 이 작업은:

- 영상 1편당 검토 시간이 길고, 검토자의 숙련도에 따라 결함 누락/오분류 편차가 크다.
- 관경·거리·관로번호 등 화면 자막(OCR 대상)을 사람이 직접 옮겨 적어야 한다.
- 결과물이 표준화된 엑셀 조사표 형태로 나와야 실무에 바로 쓸 수 있다.

**AI CCTV**는 이 과정을 YOLO 기반 딥러닝 결함 탐지 + OCR 자동 판독으로 보조/자동화하여, 검토자가 "탐지된 결과를 확인·보정"만 하면 되는 워크플로로 바꾸는 것을 목표로 한다.

## 2. 제품 개요

Windows용 **로컬 데스크톱 애플리케이션**(pywebview 네이티브 창 + FastAPI 백엔드 + JS 프론트엔드, 별도 설치형 웹서버 아님)으로, 기존 tkinter 버전(`ver3.1_AI_CCTV_YOLO`)을 대체한다.

> "하수관로 CCTV 영상에서 YOLO(`best.pt`)로 결함을 자동 탐지하고, 편집 가능한 결과표와 엑셀 보고서를 생성하는 데스크톱 앱." — 앱 README

핵심 가치 제안:
1. 영상을 큐에 넣기만 하면 결함 프레임을 자동 추출·탐지·주석 처리한다.
2. 화면 자막(거리/관경/관로번호/현장명)을 OCR로 자동 판독해 결과표에 채운다.
3. 결과를 표에서 바로 검수·수정(오탐 제외, 값 편집)하고 엑셀로 즉시 내보낸다.

## 3. 사용자 및 사용 시나리오

- **주 사용자**: 하수관로 CCTV 조사 결과를 정리하는 현장/사무 담당자 1인 (동시 다중 사용자 미고려, DB 없이 메모리 상태로 동작).
- **핵심 시나리오**:
  1. 조사 영상(mp4/avi/mkv, 여러 개) 선택 → 큐 등록
  2. 분석 실행 → 진행률(프레임 추출/YOLO/OCR 단계) 실시간 표시
  3. 결과표에서 결함별 신뢰도 임계값·클래스 필터로 검토, 플레이어에서 해당 시점으로 바로 이동해 육안 확인
  4. 오탐 체크, 값 수정(관경/거리/관로번호/결함종류/비고), 필요시 행 수동 추가/삭제
  5. "엑셀로 내보내기" → 표준 조사표(`CCTV_조사_집계표.xlsx`) 생성, 프레임 이미지 임베드

## 4. 현재 구현 범위 (As-Is, 2026-08-11 기준)

### 4.1 파이프라인 (영상 입력 → 출력)

| 단계 | 구현 위치 | 설명 |
|---|---|---|
| 1. 조사 시작점 자동 인식 | `backend/ocr.py` | 영상 앞 30초를 2초 간격으로 PaddleOCR 스캔, "조사시작/시작" 텍스트로 시작 오프셋 결정 (기본 OFF — 0초부터 전체) |
| 2. 프레임 추출 | `backend/frames.py` | 시작~끝 구간 2초 간격으로 JPEG(품질 80) 추출 |
| 3. 결함 탐지 | `backend/yolo_infer.py`(로컬) / `backend/yolo_remote.py`(원격) | Ultralytics YOLO, conf 0.10 / imgsz 960, **바운딩박스 탐지만 지원 (세그멘테이션 미지원)** |
| 4. 자막 오탐 필터 | `backend/overlay_filter.py` | 위도/경도 등 화면 자막 영역에서 나온 탐지를 제거 |
| 5. 자막 메타데이터 OCR | `backend/ocr.py` | 거리/관로번호/관경/현장명/맨홀 등 8종 판독 |
| 6. 중복 거리 플래깅 | `backend/rows.py` | 동일 거리값이 2회 이상 검출되면 "확인필요" 표시 (자동 삭제 아닌 인간 검수 유도). 수동 추가 행은 제외 |
| 7. 주석 처리 | `backend/annotate.py` | bbox + 한글 라벨 + confidence%를 프레임에 오버레이 |
| 8. 엑셀 출력 | `backend/excel_export.py` | 주행방향/영상위치/관로번호/관경/거리/결함종류/비고 + 프레임 이미지 임베드 |
| 9. 야장 PDF 출력 | `backend/pipeasset_pdf.py` | 파이프에셋 야장(하수관거 현황 조사 보고서) A4 형식 |

엑셀·PDF 모두 **관로 단위로 따로 뽑거나 전체를 한 파일로** 뽑을 수 있다.

### 4.2 추론 실행 위치 (로컬 vs 원격)

- 기본값은 **원격 추론**: Google Colab GPU를 Flask 서버로 노출하고 고정 ngrok 도메인으로 터널링(`notebooks/inference_colab_server.ipynb`). 로컬 PC는 CPU만 있어도 됨(`ultralytics`/`torch` 로컬 설치 불필요).
- UI에서 "Colab 추론 서버" URL을 직접 지정 가능, 비워두면 로컬 추론(`yolo_infer.py`)으로 전환.
- 원격은 프레임을 24장씩 청크로 나눠 전송, 청크 단위 에러 격리로 GPU OOM 시 전체 실패 방지.
- 로컬도 `YOLO_CHUNK_SIZE`(기본 8)로 나눠 넘긴다 — 리스트를 통째로 주면 ultralytics가 한 배치로 올려 112장에서 3.7GB 할당 실패가 났다.

**실행 진입점 3가지**

| 파일 | 용도 | 추론 위치 | 로그인 |
|---|---|---|---|
| `main.py` | 데스크톱 exe (pywebview 창) | Colab 원격 | 없음 |
| `serve_web.py` | 웹 배포 | Colab 원격 | 있음 |
| `serve_web_cpu.py` | 웹 배포 (Colab 없이) | 이 PC의 CPU | 있음 |

CPU 로컬 추론은 yolo11l·imgsz 960 기준 프레임당 약 0.44초(22코어)로, 6분 영상이 1~2분이면 끝난다.

### 4.3 UI / 상호작용 기능

- **영상 플레이어**: MJPEG 스트리밍 재생, 0.5~2.5배속, 확대/축소·드래그 팬, bbox 실시간 오버레이, 키보드 단축키(스페이스/화살표).
- **결과표**: **선택한 관로만 표시**(여러 관로가 한 줄로 이어지지 않게), 중복거리 그룹별 접기, 셀 더블클릭 인라인 수정, **결함항목 코드 콤보박스**(`GET /api/config/defect_codes`), confidence 슬라이더(0~95%) + 클래스별 토글(표·오버레이 공용 필터), 오탐 체크박스(통계·엑셀 제외), 행 수동 추가/삭제, Shift+클릭 범위 선택, ↑/↓·Enter 키 이동(플레이어 자동 동기화), 전체 초기화.
  - 커서(키보드 위치)와 선택(삭제 대상)은 **별개**다. 그룹을 펼치는 것은 '보기'일 뿐이라 선택을 건드리지 않는다.
  - 수동 추가 시 그 초가 이미 차 있으면 실패하지 않고 가장 가까운 빈 초에 넣은 뒤 위치를 알려준다.
- **내보내기 범위 선택**: 엑셀·PDF를 뽑을 때 "선택한 영상만 / 분석한 전체" 중 고른다. 전체로 뽑으면 파일명에 `전체N건`이 붙는다.
- **통계 탭**: 영상별/전체 결함 클래스별 카운트(오탐 제외). 화면이 관로별로 나뉘어도 통계는 항상 전체를 본다.
- **진행 상황**: WebSocket(`/ws/progress`)으로 단계별 로그·진행률·결과 실시간 push.
- **네이티브 파일 다이얼로그**: 영상 다중 선택, 엑셀 저장 경로 선택 (pywebview API, 브라우저 단독 실행 시 `prompt()`로 대체).

### 4.4 데이터/상태 관리

- 상태는 `state.py`가 메모리로 들고, `session_store.py`가 **`session.json`으로 자동 저장**한다. 영상 분석이 끝날 때마다·표를 편집할 때마다 저장되고, 다시 켜면 복원된다.
- 현장명은 **관로별로** 보관한다(`state.site_name_of`) — 관로마다 현장이 다를 수 있다.
- 세션별 임시 디렉터리에 추출 프레임 저장.
- 웹 진입점(`serve_web.py` / `serve_web_cpu.py`)은 `backend/auth.py` 기반 로그인이 있다(`AUTH_USERS` 환경변수). 데스크톱 exe(`main.py`)는 로그인 없음.
- **사용자별 상태 격리는 없다** — 여러 사람이 같은 웹 인스턴스에 붙으면 같은 상태를 공유한다.

### 5.1 확정된 구조 — 필터(분류기)와 YOLO 병렬

```
프레임 → 분류기(다중클래스, 24종) ─┬─ 결함확률 → 상위 20%가 표의 행이 된다
                                └─ 이름(확신 90%↑) ─┐
        YOLO(test3, 16종) ────────── 이름+박스 ──────┤→ 후보로 나란히 (검수자가 최종 선택)
        LLM(선택, 기본 꺼짐) ──────── 이름 ───────────┘
```

이전 판(§5.4의 "2단계: 필터→YOLO 직렬")과 다르다. **필터가 위치를 못 그리는 대신
1차 이름도 낸다** — YOLO가 학습하지 못한 종류(BC·DE·DF·DG·IF·LD 등)를 필터가 이름으로
메운다. 분류기 점수가 낮은(관 밖 등) 프레임의 YOLO 검출은 버려 오탐을 줄인다
(`YOLO_DROP_BELOW=0.10`).

### 5.2 배포 모델 및 실측 성능

| 역할 | 파일 | 원본 | 핵심 수치 |
|---|---|---|---|
| 필터+1차 이름 | `apps/AI_CCTV/assets/classifier.onnx` | `C_eff_mc/best_acc.pt`, 24클래스 EfficientNet-B0 | AUC **0.9906**, 결함재현율 **96.0%**(정상오탐5%), 관밖오탐 **0%** |
| 검출(2차 이름+박스) | `apps/AI_CCTV/assets/best.pt` | test3(16종), mAP50 **0.703** | 야장 기준 재현율 **36.0%**(105/292장, 유출 없는 검증셋) |
| 옛 이진필터(폴백) | `apps/AI_CCTV/assets/filter.onnx` | v3 이진, 관밖오탐 39% | 분류기 로드 실패 시에만 사용 |

**YOLO는 test5(17종)에서 test3(16종)로 교체했다** (2026-08-15). test5를
`testset_bycode`(S20/AIHub만 구성)로 재면 이름정확도 90.0%였는데, 같은 종류를
야장 사진 기준으로 재니 33.3%로 무너졌다. **원인은 학습 데이터 유출로 확정됐다** —
스윕 결과 폴더의 `used_files.csv`(그 run이 실제로 쓴 원본 파일 목록)와 대조하니
`testset_bycode` 결함 455장 중 **259장(56.9%)이 test5의 train에 들어 있었다.**
즉 90.0%는 일반화가 아니라 암기를 잰 값이다.

`testset_bycode`는 test3와도 249장 겹치므로 **YOLO 계열 평가에는 쓸 수 없다.**
대신 test3 학습분을 전부 제외해 새로 만든 `test3_holdout`(492장, 야장 80%,
겹침 0장 확인)으로 재서 야장 기준 재현율 36.0%를 얻었다 — 이것이 신뢰할 수 있는
유일한 YOLO 수치다.

분류기(§5.2 표 1행)는 야장 중심 `clsdata_old_v6`로 학습해 `testset_bycode`와
겹치지 않으므로 그 판의 값을 그대로 신뢰해도 된다.

**필터(분류기)는 위 표의 값이 결함코드 23종(ETC 제외) 전체에서 실측됐다** —
23종 중 14종은 판정률 100%, 관 밖(맨홀 등) 오탐이 v3의 39%에서 0%로 사라졌다.
다만 **이 값은 결함이 확실히 찍힌 잘라놓은 사진 판**(`testset_bycode`,
정상:결함 비율을 인위적으로 맞춤)에서 잰 것이고, **연속 실영상에서의 검증
(베타테스트)은 아직 진행하지 않았다.**

| **UI 한글 라벨 매핑** (`backend/config.py`) | 비정형 | 매핑에 없는 클래스는 모델 원본 코드로 표시 |
| **세그멘테이션 목표(스윕 설정)** (`configs/sweeps/test4_seg.example.yaml`) | 8개 | 앱 미연동, boxes만 처리 |

BC·DE·DF·DG·IF·LD 6종은 YOLO에 클래스 자체가 없어 필터가 유일한 판독자다.

## 6. 비기능 요구사항 / 아키텍처 제약

- **오프라인 내성**: 학습은 인터넷이 불안정한 워크스테이션에서도 무인 실행 가능하도록 설계(`scripts/sweep`가 별도 문서 대상, 참고만). 반면 **배포 앱의 기본 추론 경로는 인터넷(Colab+ngrok) 의존** — 상충되는 지점이며 리스크로 관리 필요(§8).
- **단일 사용자, 로컬 실행**: 서버 배포/동시접속/권한 관리 요구사항 없음(현재 설계 기준).
- **저사양 대응**: 로컬 추론은 선택 사항이며 CPU만으로도 원격 모드 구동 가능하도록 설계됨.
- **한글 처리**: bbox 라벨 한글 렌더링(PIL, CJK 폰트 미탐지 시 영문 폴백), OCR 대상도 한글 자막 포함.

## 8. 로드맵 제안

> **2026-08-15 갱신** — 모델 개발(줄기 2·3)은 이 시점으로 마감했다. §5.4까지의
> 실험을 거쳐 필터(C, 다중클래스)+YOLO(test3) 병렬 구조로 확정했고, 이후 신규
> 모델 학습은 계획에 없다. 아래는 그 상태를 반영해 갱신한 다음 단계다.

현재 작업은 세 줄기로 나뉜다.

| 줄기 | 대상 | 평가 기준 | 상태 |
|---|---|---|---|
| **1. app** | `apps/AI_CCTV` — UI·UX·작업흐름 | 작업흐름이 매끄러운가 | 진행 중 |
| **2. YOLO 학습** | `configs/sweeps`, `scripts/sweep` — 결함 **위치** | mAP | **마감 (test3 채택)** |
| **3. 필터 학습** | `scripts/classifier` — 결함 **유무·이름** | 놓침(recall) / 오탐(FPR) | **마감 (다중클래스 C 채택)** |

1. **실영상 베타테스트(우선순위 최상)**: §5.2의 성능은 전부 잘라놓은 사진 판이다.
   연속 실영상(카메라 이동·조명변화·평범한 구간 다수)에서 조사표 대조 검증이
   다음 단계 — `scripts/classifier/eval_pipeline_on_videos.py`가 그 골격
   (`인식률.xlsx` 대조, ±0.3m 또는 ±3초 허용). (줄기 1)
2. **추론 인프라 이중화**: Colab+ngrok 단일 의존 제거 — 자체 GPU 서버 또는 안정적 클라우드 추론 엔드포인트로 대체. `serve_web_cpu.py`가 폴백 역할을 하지만 정식 경로는 아니다.
3. **세그멘테이션 연동**: `test4_seg` 결과를 `yolo_infer.py`/`yolo_remote.py`/`annotate.py`에 마스크 처리 경로 추가, UI에 폴리곤 오버레이 지원.
4. **웹 사용자별 상태 격리**: 현재 전역 상태 하나라 동시 접속이 서로를 덮어쓴다.
5. **병렬 합산 성능 재측정**: 지금 있는 합산 수치(YOLO+분류기 82.9% 등)는
   유출된 판(`testset_bycode`)에서 나온 값이라 폐기됐다. `test3_holdout`으로
   다시 재야 병렬 구조의 실제 이득을 말할 수 있다
   ([상세](reports/2026-08-15-필터C-test3-병렬-확정.md) §8).
6. **실험 메타데이터 정합성**: `configs/detect_v2.yaml`의 빈 `names`, `detect_v2_bk_ds/metadata.yaml`의 TBD 항목 정리.
